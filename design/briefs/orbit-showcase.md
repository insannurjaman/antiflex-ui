# Orbit showcase extension

Mode: Operate. Code-led extension of the existing dashboard and antiflex Neutral world.

Confirmed: the user wants a rich, complete client-facing demo and chose the existing Orbit SaaS workspace. Preserve the incumbent identity, token palette, typography, square controls, and authored native component behavior. No concept or brand replacement is in scope.

Deliver a discoverable /examples gallery and a connected /demo workspace: overview, analytics, orders, customers, projects, activity, team, settings, profile, billing, checkout, sign-in, and onboarding. Keep /dashboard available as the original foundation example. Both sidebar and top navigation must work, including mobile disclosure, active routes, direct links, and browser history.

First viewport: a compact example toolbar with navigation-layout selection; the Orbit workspace header; ordinary named navigation; a clear task heading and real sample content. Work areas use ruled groups, semantic tables and charts, familiar forms, and existing antiflex components. No invented customers or commercial proof; all records and sample prices are explicitly illustrative.

Signature interaction: switch between sidebar and top navigation without losing the route or saved demo changes. Customer/project/team edits flow into shared activity and counts. Forms preserve meaningful state across connected views and reloads; reset clears only this demo's own sample state.

Working flows: search/filter/sort/page records; inspect and add customers; create and move projects; invite, change roles, and remove sample members; save workspace/preferences/profile; preview invoices; choose an illustrative plan and billing cycle; apply demo discounts and complete checkout to a local receipt; step through sign-in and onboarding without external authentication or payments.

Acceptance: no dead links/buttons; visible keyboard focus and associated validation; empty/loading/success states; responsive light/dark layouts at 390, 768, and 1440 widths; semantic accessibility scans; production build and scoped interaction checks; fresh independent finish review and documentation handoff. Existing component APIs and global theme values remain unchanged.
